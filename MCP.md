# Sigma Seller: MCP и чат с данными магазина

Реализовано в Community-исходниках 26 октября 2026. Публичный сайт этим пакетом автоматически не обновляется.

## Для продавца

Откройте «Подключения ИИ» (`/connections`), скопируйте адрес сервера и добавьте его как своё MCP-подключение в ChatGPT или Claude. Доступность этой функции зависит от аккаунта и настроек организации у провайдера. При подключении войдите в Sigma Seller, выберите один магазин и разрешения. По умолчанию интерфейс предлагает только чтение. Для другого магазина создайте отдельное подключение.

ИИ в таком сценарии работает в аккаунте продавца. Sigma Seller читает сохранённые данные из своей базы: запрос MCP не вызывает ИИ-провайдера и не обновляет данные WB. Если данные отсутствуют, чат получает пустую выборку или `null`, а не выдуманный нулевой результат.

Чат внутри сайта находится на `/assistant`. Он использует сохранённый ключ OpenAI или Anthropic выбранного рабочего пространства. Нужны роль менеджера или выше и явное согласие на расходы провайдера. Ключ выбирается заново перед каждым платным запросом; общего резервного ключа нет. Один вопрос может вызвать до четырёх запросов к модели, до 12 обращений к инструментам и до 1600 токенов ответа в каждом запросе. На рабочее пространство разрешён один активный разговорный запрос. Модель можно указать самостоятельно; её доступность и тариф определяет провайдер. История беседы остаётся в открытой странице, черновики и предложения сохраняются на сервере.

## Операции

| Инструмент | Данные / результат |
|---|---|
| `list_shops` | Магазин, выбранный при авторизации, последняя завершённая успешная синхронизация |
| `sales_summary` | Продажи и доступные финансовые итоги за период до 90 дней, денежные показатели в рублях |
| `search_products` | Поиск по названию, артикулу продавца или nmId; описание, время обновления, пагинация |
| `get_stocks` | Сохранённые остатки по складам и время снимка |
| `list_feedback_questions` | Отзывы / вопросы и ответы без отдельного поля имени покупателя |
| `advertising_summary` | Сводка рекламы по товарам за период и отдельный постраничный список сохранённых кампаний |
| `save_draft` | Сохранение текста; ничего не публикует |
| `propose_action` | Предложение точного изменения для отдельного подтверждения на сайте |

Пагинация ограничена 30 строками и объёмом текста, курсор связан с магазином и фильтрами. Оперативная выручка и финансовые отчёты возвращаются раздельно; их нельзя складывать или называть чистой прибылью. Описания, отзывы и вопросы отмечены как недоверенный текст.

Разрешения: `seller.read` — чтение для участников; `seller.drafts` — черновики для менеджеров и выше; `seller.actions` — предложения изменений только для владельца. Права проверяются при каждом вызове, включая внутренний чат. Выход из команды и изменение роли отзывают ранее выданные подключения; повторное приглашение не восстанавливает старые токены. Сброс пароля кодом восстановления тоже отзывает подключения.

## Подтверждение действий

Доступны предложения ответа на отзыв, ответа на вопрос, изменения цены со скидкой продавца, замены описания карточки и остановки рекламной кампании. Поля не редактируются после создания. Предложение действует 15 минут и связано с конкретными пользователем, магазином и подключением.

Модель не имеет инструмента исполнения. На странице «Подключения ИИ» автор предложения проверяет все параметры и ставит отдельный флажок перед отправкой. Сервер проверяет хеш предложения и атомарно помечает его выполняющимся до сетевого запроса. Повторное или одновременное нажатие не повторяет отправку. При неопределённом сетевом результате требуется ручная сверка в кабинете WB; автоматического повтора нет. «Принято WB» означает приём запроса, а не подтверждение завершённой публикации.

Перед заменой описания сервер читает карточку WB, сверяет её nmId и прежнее описание, сохраняет размеры, характеристики, бренд, GTIN, документы и отметку маркировки. Несовпадение прежнего текста или неполная карточка останавливает отправку. WB не предоставляет здесь условную атомарную запись: параллельное ручное редактирование карточки в кабинете во время отправки следует исключить.

## Установка и настройки оператора

Установите зависимости по lock-файлам, соберите API и сайт согласно README. MCP использует официальный TypeScript SDK `@modelcontextprotocol/server` 2.4.0 и stateless Streamable HTTP с JSON-ответами. SSE-потока уведомлений нет. Дополнительная миграция — `0151_seller_mcp.sql`; новая пустая база создаётся штатным `init-community-db.mjs`. На существующей базе после резервной копии используется обычный migration runner, а не инициализатор пустой базы. Ошибки новых Community-миграций останавливают запуск.

Настройки API:

```dotenv
MCP_PUBLIC_ORIGIN=https://your-domain.example
MCP_CLIENT_REDIRECT_HOSTS=chatgpt.com,claude.ai,claude.com
WB_PARTNER_BILLING_ACCEPTED=0
MCP_WB_WRITES_ENABLED=0
```

`MCP_PUBLIC_ORIGIN` — публичный origin без пути, запросов и учётных данных. В production требуется HTTPS. Домен клиента возврата проверяется по точному имени; для другого доверенного клиента оператор должен явно добавить его домен. Клиенты регистрируются динамически, без общего клиентского секрета. Локальные loopback-адреса разрешены только вне production.

Публичные адреса:

- `/mcp` — инструменты, принимает только отдельный Bearer-токен подключения;
- `/.well-known/oauth-protected-resource/mcp` и корневой вариант — метаданные ресурса;
- `/.well-known/oauth-authorization-server` — метаданные авторизации;
- `/oauth/register`, `/oauth/token`, `/oauth/revoke` — регистрация, выдача и отзыв;
- `/connections/authorize` — согласие в браузере, требует обычного входа.

Код авторизации одноразовый, срок 5 минут, PKCE только S256. Токен доступа действует до 15 минут, само подключение — 30 дней; refresh-токены вращаются. Повторное использование потраченного кода или refresh-токена отзывает всё подключение. В базе хранятся хеши кодов и токенов. Audience/resource, client_id и redirect_uri связаны с выдачей. Не включайте запись тел OAuth-запросов или заголовка Authorization в журналы прокси.

В Next.js есть отдельные публичные маршруты протокола. Они не передают cookies, общий API-ключ и impersonation-заголовки. Для публичного многопользовательского запуска предпочтительно направить `/mcp`, точные OAuth-маршруты и discovery-маршруты напрямую с доверенного обратного прокси на API, сохраняя настоящий адрес клиента. Иначе Next.js-прокси объединяет обращения под своим IP, и лимит регистрации 5 клиентов в час разделяется всеми продавцами. API должен быть закрыт от прямого внешнего доступа; прокси должен перезаписывать адресные заголовки, а не доверять значениям из интернета.

Отправка MCP-предложений в WB выключена по умолчанию. Для неё нужны отдельный флаг `MCP_WB_WRITES_ENABLED=1` и согласие оператора оплачивать WB API — `WB_PARTNER_BILLING_ACCEPTED=1`. Если договор действительно бесплатный, вместо согласия на оплату можно использовать `WB_PARTNER_BILLING_VERIFIED_FREE=1`. Флаги не меняют тариф, не устанавливают денежный лимит и не разрешают общие платные ключи ИИ или почты. Согласие на оплату само по себе не включает запись: каждое действие по-прежнему требует отдельного подтверждения продавцом на сайте. Переключатель записи относится к новым подтверждениям MCP; остальные ранее существовавшие маршруты WB имеют свои проверки. Он не является общим сетевым выключателем всех обращений WB.

Рабочие очереди старой версии автоматически не запускаются и не архивируются этим модулем. Перед выпуском всей Community-версии нужно решить вопрос ранее накопленных заданий и исключить платные общие ключи из окружения API и worker.

## Подписка ChatGPT внутри сайта

Удалённый MCP и использование подписки внутри стороннего сайта — разные интеграции. Официальная документация Sign in with ChatGPT направляет удалённо размещённые приложения на согласование доступа. Пока подтверждения для Sigma Seller нет, интерфейс честно показывает недоступность этого режима. Поддельного входа, копирования cookies, чужого client_id и скрытого перехода на платный API нет. Сам механизм использования подписки внутри сайта **не реализован и не активирован**: его контракт и выдаваемые приложению разрешения необходимо подтвердить с провайдером. Доступные сейчас сценарии в коде — внешний ChatGPT/Claude через MCP и внутренний чат с ключом продавца.

## Проверки и границы

`pnpm run test:community` выполняет тесты с PostgreSQL-совместимой PGlite и официальным MCP-клиентом. Проверяются OAuth/PKCE, ресурсы и redirect, роли, отзыв и replay, отделение магазинов, сумма в копейках/рублях, отсутствие внешних вызовов инструментов чтения, подтверждения и повтор, оба протокола ИИ на подставных ответах, сохранение полей карточки. Платные генерации и реальные записи WB тестами не выполняются.

Для окончательного выпуска всё ещё нужны проверка конкретного ChatGPT/Claude-аккаунта через публичный HTTPS-адрес, проверка доступности выбранных моделей с ключами продавца и условий WB. Массовая нагрузка и все исторические функции проекта не объявляются проверенными.
